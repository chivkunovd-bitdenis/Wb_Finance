# Кликабельный макет: разворот таблицы по дням

## Сценарий (контракт)

**Кто участвует:** пользователь WB Finance, который просматривает ежедневные финансовые строки.

**Действие пользователя:** на существующем дашборде выбирает маркетплейс в общей верхней панели и нажимает кнопку разворота в заголовке таблицы по дням. Возвращается кнопкой «Свернуть» или Escape.

**Что человек должен увидеть:** исходный интерфейс приложения остаётся без перестановки и переделки. В обычном режиме таблица сохраняет свой прежний размер и место; добавляется только кнопка разворота. В раскрытом режиме сама таблица занимает окно справа от настоящего бокового меню, а остальные блоки дашборда оказываются под ней. Для WB поверхность таблицы и обычные дневные строки получают очень мягкий розовый оттенок; для Ozon — очень мягкий голубой. Оттенок выбирается существующим переключателем маркетплейса и сохраняется при раскрытии.

**Как система обрабатывает действие:** выбор маркетплейса меняет уже существующее состояние приложения. Дополнительный React-слой прототипа находит нужную таблицу в исходных компонентах: на WB это «Детализация по дням», на Ozon и в общем режиме — таблица «Динамика по дням». Кнопка переключает локальное состояние разворота; при раскрытии карточка таблицы закрепляется по фактической границе существующего меню. Escape закрывает режим. При выходе восстанавливаются прежняя прокрутка страницы и фокус на кнопке.

**Что меняется:** только локальное отображение таблицы и состояние её разворота. Финансовые данные не отправляются и не сохраняются. Все ответы API в прототипе формируются локальными синтетическими fixtures; для изоляции приложения используется отдельный порт, поэтому браузерное хранилище основного приложения на `127.0.0.1:5173` не затрагивается.

**Чего быть не должно:** изменений существующих меню, иконок, заголовков, KPI, графиков, фильтров, названий/порядка столбцов, размеров и расположения исходных блоков; окрашивания соседних таблиц Ozon, KPI, меню или всей страницы; чередования строки «ИТОГО», плановых строк и разделителей месяцев; внешних запросов и пользовательских данных.

**Проверка «всё ок»:**
- Дано: открыт исходный дашборд с локальными вымышленными строками.
- Когда: выбран WB, затем Ozon.
- Тогда: таблица по дням получает соответствующую мягкую тему и полосы из двух дневных строк; исходные заголовок, итоги и остальные элементы остаются прежними.
- Когда: пользователь нажимает «Развернуть».
- Тогда: только нужная таблица занимает область окна от границы существующего меню до правого, верхнего и нижнего краёв; меню остаётся на месте и доступно.
- Когда: пользователь нажимает «Свернуть» или Escape.
- Тогда: восстанавливаются исходная раскладка, прокрутка и фокус.
- Когда: открыт адрес с `?baseline=1`.
- Тогда: видны те же production-компоненты, стили и fixture-ответы, но без прототипной кнопки, разворота и цветового выделения; это контроль для сравнения визуальной основы.

**Проверка «если сломалось»:** если целевая таблица отсутствует или ещё загружается, дополнительный слой ничего не вставляет и не мешает штатному состоянию загрузки/ошибки исходного экрана. При нехватке ширины прокручивается исходная внутренняя область таблицы; тело страницы не получает горизонтальную прокрутку от режима разворота.

## UX/UI Contract

- **Точка входа:** кнопка «Развернуть» в уже существующей строке заголовка целевой дневной таблицы.
- **Паттерн:** временное закрепление существующей карточки поверх соседнего содержимого, без создания нового экрана или копии таблицы.
- **Основное действие:** «Развернуть»; в раскрытом режиме та же кнопка показывает «Свернуть».
- **Вторичные действия:** Escape сворачивает таблицу; существующее боковое меню остаётся видимым.
- **Закрытие:** отдельная кнопка и Escape; клик вне таблицы ничего не закрывает; несохранённых изменений нет.
- **Прокрутка:** используется исходная внутренняя область таблицы с её штатными правилами; разворот не меняет исходные столбцы и не переносит остальную страницу.
- **Цвет:** фон карточки таблицы очень светло-розовый в режиме WB и очень светло-голубой в режиме Ozon. Только обычные дневные строки чередуются попарно: две строки базового мягкого оттенка, следующие две — немного более выраженного оттенка. Тоталы, заголовки, разделители и план-факт строки сохраняют исходное оформление.
- **Доступность:** кнопка имеет доступное имя и видимый фокус; при развороте соседнее содержимое становится недоступно для Tab и экранного диктора, а боковое меню и целевая таблица остаются доступны; после сворачивания прежнее состояние доступности восстанавливается.
- **Адаптивность:** отступ закрепления вычисляется из фактической геометрии настоящего меню; на мобильном Ozon сохраняется существующая горизонтальная панель меню и разворот начинается ниже неё. Исходная ширина меню не переопределяется.
- **Состояния:** загрузка, пустой результат и ошибка остаются состояниями исходных компонентов. Макет показывает локальные вымышленные данные без отметок или новых баннеров в интерфейсе.
- **Визуальная основа:** компоненты `App`, `Layout`, `Sidebar`, `Topbar`, `Dashboard`, `MarketplaceFinance` и исходные CSS-файлы приложения подключаются напрямую. Единственные видимые additions — кнопка и очень лёгкая цветовая тема целевой дневной таблицы.

## Для разработки

Цепочка: выбор существующего маркетплейса → исходный `Layout` переключает дерево WB `Dashboard` / Ozon `MarketplaceFinance` → прототипный React-слой находит только дневную таблицу и задаёт ей тему; клик по новой кнопке → состояние React → класс закрепления на этой же карточке, инертность соседних блоков, измеренные inset-границы меню → «Свернуть» или Escape → снятие классов, возврат прокрутки и фокуса.

Vite prototype использует alias только для исходного API-модуля и возвращает синтетические fixtures; вызовов к серверу нет. `?baseline=1` выключает только prototype-добавки. Ключи браузерного хранилища, если их используют исходные провайдеры, изолированы отдельным портом прототипа.

# Ozon как WB: что видно на экранах и почему

Этот документ фиксирует результат задачи «Ozon выглядит так же, как WB»: какие колонки WB заполнены данными Ozon, какие показывают прочерк и почему. Все цифры на снимках получены на синтетическом магазине, реальные данные продавца не использовались.

## Что сделано

Главный экран Ozon теперь использует тот же компонент дашборда, что и WB: три карточки показателей, график «Продажи, ₽», таблица «Детализация по дням» с теми же столбцами, порядком, форматированием, настройками и разворотом. Блоки «Итоги за период» и «Товары и начисления» с экрана Ozon убраны. То же касается «Артикулов» и «Себестоимости»: Ozon получает те же таблицы и ту же форму ввода, данные приходят из новых маркетплейсных эндпоинтов в формате WB.

Вторые по важности изменения касаются расчёта. Строка дня теперь складывается из известных начислений: отсутствие одной детали одной продажи больше не обнуляет всю выручку дня. Себестоимость и маржа считаются по товарам, у которых известна себестоимость, и на экране видно, какая доля выручки за это покрыта.

Третье изменение касается синхронизации. После сохранения подключения Ozon автоматически догружает данные с 1 января текущего года до вчера отрезками не длиннее 31 дня, по одному запуску на владельца; ежедневная задача (Celery beat, 06:30 по Москве) обновляет последние три завершённых дня для готовых подключений и продолжает незавершённую догрузку. Ручная кнопка осталась в «Настройках» как вторичное действие.

## Колонки: WB и Ozon

Все заголовки таблиц совпадают. Отличаются только подписи первого столбца в «Артикулах» и «Себестоимости» (SKU Ozon вместо Артикул ВБ и NM ID) и подписи в режиме «Все маркетплейсы».

| Колонка WB | Ozon | Что показано и почему |
|---|---|---|
| Дата | заполнено | Все даты периода. Дата без данных Ozon показывает прочерк во всех ячейках строки. |
| Выручка | заполнено | Сумма известных начислений продаж за день. Продажа без блока комиссии не обнуляет день: её выручка не входит в сумму, остальные учитываются. |
| Заказы ₽ | прочерк | В проекте нет источника заказов Ozon: воронка и сумма заказов есть только у WB. Колонка сохранена, значения честно пустые. |
| Ком, % ком | заполнено | Комиссия из блока commission каждой продажи (знак как у WB, расход положительный). |
| Лог, % лог | заполнено | Логистика из блока delivery каждой продажи. |
| Штрафы | заполнено | Сумма распознанных штрафных начислений. Ноль означает, что таких начислений в выгрузке не было, а не то, что штрафов точно нет. |
| Себес, доля себеса | заполнено, если известна себестоимость | Сумма себестоимости товаров, у которых она внесена и количество продаж подтверждено. Доля считается от всей выручки дня, поэтому при неполном покрытии она ниже фактической. Прочерк только если ни у одного товара себестоимость не известна. |
| Налог | заполнено | Выручка дня × ставка налога WB (управленческая оценка, не декларация). |
| Реклама, % рекл | ноль, не проверено | В выгрузке Ozon на этих данных не найдено начислений рекламы, поэтому показан ноль. По контракту это должно быть неизвестным значением. Нужно решение владельца (см. ниже). |
| Хран, % хран | ноль, не проверено | То же для хранения: начислений хранения в выгрузке не было. |
| Доля расходов ВБ | заполнено | Формула WB (комиссия, логистика, штрафы, хранение, реклама) от выручки. |
| Опер. расходы | заполнено или прочерк | Внесённая владельцем сумма за день. Если полнота расходов не подтверждена в настройках, колонка показывает прочерк. |
| Маржа, % маржи | заполнено, если подтверждены расходы | Маржа по товарам с известной себестоимостью минус расходы за день. Если полнота операционных расходов не подтверждена, маржа неизвестна. |
| ROI | заполнено, если известна себестоимость | Маржа ÷ себестоимость по тем же товарам. |

Во всех колонках, кроме «Заказы ₽», прочерк означает отсутствие данных, а не ноль: день без данных, товар без себестоимости или неподтверждённые расходы.

## Карточки показателей и подписи

- Выручка: сумма известных дней. Подпись «без учёта N дн.» показывает, сколько дней периода без данных Ozon в сумму не вошли. Прочерк только если за период нет ни одного дня с данными.
- Маржа: сумма маржи по товарам с известной себестоимостью. Подпись «маржа по товарам с себестоимостью (X% выручки)» показывает, какая доля выручки периода за ней стоит.
- ROI: маржа ÷ себестоимость по тем же товарам, подпись «по товарам с себестоимостью».

## Одна подсказка вместо набора предупреждений

Над экранами Ozon показывается одна жёлтая плашка в стиле WB, одной фразой: сколько дней без данных, какая доля выручки с известной себестоимостью, или текущее состояние подключения и догрузки. Полный список замечаний, пропущенные дни, сведения о синхронизации и кнопка «Перечитать статус» раскрываются по «Подробнее».

## Что не входит в эту работу и что не проверено

- Настоящие данные Ozon не использовались; проверка на синтетике. Наличие возвратов, рекламы и хранения в реальных выгрузках не подтверждено этим стендом.
- Возвраты: в контракте сказано, что направление возвратов не подтверждено. Поэтому себестоимость товара с возвратом по-прежнему неизвестна. Вопрос к владельцу: можно ли оценивать возвращённые единицы по себестоимости.
- Реклама и хранение показаны нулём там, где в выгрузке нет таких начислений. По контракту это неизвестные значения. Нужно решение владельца.
- Противоречие с контрактом: в docs/ozon-finance/CONTRACT.md написано, что при любой неизвестной себестоимости день получает себестоимость и маржу null. Новое правило для дашборда и артикулов: суммы по товарам с известной себестоимостью, неизвестная часть явно подписана. Этот документ отражает новое правило; сам контракт пока не переписан.
- План-факт для Ozon не включён: планы хранятся на магазин и сравниваются только с WB. Пункт в настройках таблицы виден, но недоступен вне WB.
- Воронка и ИИ-модуль остаются только для WB, как и раньше.
- «Опер. расходы» Ozon: записи только по дням с суммой, комментариев в модели Ozon нет, поэтому поле комментария скрыто.
- Мобильная ширина не проверялась.
- Старый файл frontend/e2e/marketplace-finance.spec.js тестирует удалённый экран и не запускался; его надо переписать отдельно.
- Celery beat и реальный брокер не запускались: поведение задач покрыто тестами с подменами.
